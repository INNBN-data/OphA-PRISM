# Reproducibility and provenance

## Evidence classes

| Material | Interpretation |
| --- | --- |
| `results/author_reported_metrics.yaml` | Author-supplied study summaries; not recomputed by this release |
| `runs/private/<run>/` | Outputs generated by a specified execution, with its source and configuration hashes |
| `tests/` | Artificial software fixtures; no clinical validation |
| `MANIFEST.sha256` | Integrity of the distributed public files |

The analytical code does not read the reported-results YAML as a training objective, calibration target, or expected test result. Disagreements between records, code, and manuscript values require investigation and documented correction.

## Execution records

Preserve input-file hashes, the complete dictionary, ordered predictors, patient split assignments, preprocessing objects, selected features, hyperparameters, calibration objects, fitted estimators, package versions, seeds, and failure logs. The workflow records dataset, configuration, code, and feature-order fingerprints for nested-fold jobs. Resume requires matching fingerprints and saved-output hashes.

The historical model identifier v1.2.0 and reference software version 1.0.1 are distinct. Current file hashes establish present content; dated repository or institutional records are needed to support a historical lock. An actual archival DOI or repository commit can be added after it exists.

## Historical reproduction

Material implementation differences are specified in [METHODS.md](METHODS.md) and the required evidence is listed in [IMPLEMENTATION_VERIFICATION.md](../server_audit/IMPLEMENTATION_VERIFICATION.md). The Python imputation backend, calibration allocations, conformal reporting repeat, and spline baseline are reference specifications. They have not been verified as the procedures that generated the historical results.

The reserved 2026 outcomes have already been reported. Evaluation of a newly specified procedure in those patients remains a same-center assessment; it does not establish a newly untouched validation cohort. Historical predictions may be evaluated with their original provenance.

## Disclosure

Individual records, probabilities, prediction sets, fitted objects, and per-patient explanations remain on the institutional server. Only approved metadata and aggregate outputs may be exported. The release allowlist is independent of the private run directories. Further details are in [DATA_GOVERNANCE.md](DATA_GOVERNANCE.md).
